# VOICE-TEMPLATE.md — build your byline's VOICE.md from this

Copy this file to `VOICE.md` in the same directory and fill it in for the person whose
name goes on the writing. Delete the instruction blocks (the indented *How to fill
this* notes) once you've replaced them.

**Read this header before filling anything in.** This project learned the hard way —
five documented corrections in its first weeks, preserved in SKILL.md's case law — that
a voice profile drifts toward mimicry unless it is built under these rules:

1. **CRAFT.md is the North Star; this file is a tiebreaker.** It is opened only where
   craft leaves two or more good versions of a sentence and you need to pick one. If a
   sentence that sounds more like the author is worse writing than the plain one, the
   plain one wins, every time, without appeal.
2. **No word list in this file is ever a source to draw from.** Lists may say *remove
   these* or *these are facts*; never *use these*. A vocabulary list is the most
   executable content in an instruction file — it can be applied by pattern match, so it
   will be — and a word inserted because a list said so is a cliché by construction.
3. **Never state a voice marker as a minimum.** Caps are safe because they can only
   remove. Floors manufacture mannerisms: "at least one X per piece" installs X where
   the author would never have put it.
4. **Do not record corpus measurements.** No sentence-length statistics, no connective
   percentages, no "their most-used intensifiers." The first build of this skill mined
   ~196,000 words of its author's speech into exactly that, reframed it three times as
   "recognition only," and drafts kept executing it as a shopping list anyway. It was
   deleted. Whatever sits in an instruction file eventually gets executed as
   instruction.
5. **A disclaimer does not neutralize an imperative.** If a passage should not be
   executed, do not write it in the imperative, whatever its section header claims.

What actually makes text read as one person, per Zinsser: firm opinions stated without
hedging, specificity so particular it could only be one person's, and writing for an
audience of one. Conviction plus concrete detail. Not tics. That is why Part 2 is the
largest part of this file and the only one used for selection.

## Header: the relationship (keep this text)

**CRAFT.md is the North Star. This file is a tiebreaker.** Write by craft alone. Open
this file at the point where craft has produced more than one good version of a sentence
or a paragraph; it tells you which of the good options sounds like the person whose name
is on the piece. Where the craft answer is singular, this file has nothing to add.

**Two parts of this file are not tiebreakers and bind always:** Part 3 is a fabrication
guardrail (never invent a story, quote, number, or credential), and Part 4 carries the
register boundaries, the NEVER list, and the identity guardrails. Getting a fact about
the author wrong is not a style miss.

> *How to fill this:* add a two-to-four line calibration sketch of who the author is —
> profession, era, what they write about, for whom, and their temperament in one clause
> each (e.g., "precise about facts, blunt about takes, warm about people").

## Part 2 — Substance: what they believe and how they argue

Voice without substance is mimicry. Generated text should draw its positions from this
spine, and argue the way the author argues. This is the part the selection step actually
uses.

## Part 3 — The story bank

This bank is a FABRICATION GUARDRAIL, not a content quota. Most working writers' output
carries no personal story at all; the receipt is more often a number, a mechanism, a
source, or plain fresh reasoning. Never reach for an anecdote to make a piece "sound
like" the author.

Fabricating personal stories is FORBIDDEN. When a piece genuinely earns a story, the
entries below are the only permitted ones. If none fit, write the piece without one.

> *How to fill this:* verified stories only — things the author has told you directly or
> published themselves, recorded with the facts exactly as they tell them. Give each
> entry the flags it needs: NDA scrub requirements, attribution notes (whose line is
> whose), verify-before-publishing flags on numbers, and overuse warnings. Group by era
> if that helps retrieval. Also record what may NOT be used, by name — unverified
> claims, other people's medical or legal events, anything under embargo.

## Part 4 — Register boundaries and the never-do list

These bind every sentence, whether or not there were options.

> *How to fill this:*
> - **Profanity and heat ceilings per channel**, measured against what the author
>   actually does, not what they say they do.
> - **The corporate-speak removal list** (safe: it only removes). Start from: leverage,
>   synergy, ecosystem, disrupt, pivot (unless literal), scale as a verb, alignment,
>   bandwidth, circle back, deep dive, move the needle.
> - **The NEVER list**: verified absences. Things the author never does — coined
>   frameworks, listicle spines, audience-pandering CTAs, engagement bait, whatever the
>   corpus shows a true zero on. State each as a prohibition, and state exceptions
>   explicitly with their binding location (e.g., the FORMATS.md book dial).
> - **House punctuation policies**: em-dash policy, emoji policy, curly-vs-straight
>   quotes per output medium.
> - **Identity guardrails**: exact name spelling, exact role title, how credentials are
>   scoped ("claims X expertise only first-person and only in Y contexts"), any
>   phrasing rules for stories involving famous names or clients.
